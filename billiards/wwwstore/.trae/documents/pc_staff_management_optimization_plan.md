# PC端人员管理功能优化方案

## 一、现状分析

### 1.1 员工管理功能
当前员工管理(`EmployeeManagement.tsx`)包含以下角色：
- `owner` - 老板
- `manager` - 店长
- `cashier` - 收银员
- `waiter` - 服务员
- `assistant` - 助教

### 1.2 助教管理功能
助教管理是独立的功能模块，包含：
- 助教列表管理
- 等级系统（初级、中级、高级、金牌）
- 排班管理（通过`ScheduleManager`）
- 评价管理

### 1.3 存在的问题

| 问题 | 描述 | 影响 |
|------|------|------|
| 角色定义不一致 | PC端硬编码角色配置，与后端`RoleConstants`不一致 | 维护困难，容易出错 |
| 员工与助教无关联 | 助教表和员工表独立，助教登录后无法查看完整信息 | 数据不一致，用户体验差 |
| 新增助教流程不完整 | 新增助教时没有同步创建员工记录 | 助教无法正常登录系统 |

---

## 二、优化方案

### 2.1 统一角色定义常量

**目标**：将前端角色配置统一，与后端`RoleConstants`保持一致

**修改文件**：
- `src/lib/types/index.ts` - 添加角色类型定义
- `src/app/employees/components/EmployeeManagement.tsx` - 使用统一常量

**角色配置表**：

| 角色标识 | 显示名称 | 权限说明 |
|----------|----------|----------|
| `owner` | 老板 | 全部权限 |
| `admin` | 管理员 | 系统管理权限 |
| `manager` | 店长 | 门店管理、订单、员工、财务 |
| `cashier` | 收银员 | 收银结算、订单、会员查询 |
| `waiter` | 服务员 | 台桌服务、商品配送 |
| `assistant` | 助教 | 陪练服务、教学服务 |

### 2.2 建立员工与助教的关联关系

**方案选择**：采用之前讨论的方案A

**数据库结构**：
```
bi_busi_employee (员工表)
└── id (主键)

bi_busi_assistant (助教表)
├── id (主键)
└── employee_id (外键，关联员工表)
```

**后端API修改**：
- 创建/更新助教时，自动同步员工记录
- 查询助教时，可关联查询员工信息

### 2.3 优化新增助教流程

**新增助教时的处理逻辑**：
```
用户填写助教信息 → 提交
        ↓
后端创建员工记录 (role = assistant)
        ↓
获取员工ID
        ↓
创建助教记录 (employee_id = 员工ID)
        ↓
返回成功
```

**优势**：
- 助教自动拥有员工身份
- 可正常登录系统
- 数据一致性保证

## 四、风险评估
