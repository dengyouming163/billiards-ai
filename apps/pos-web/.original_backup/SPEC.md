# 商业台球系统 - 收银端 SPEC

## 1. Concept & Vision

**场景定位**：专业台球厅收银终端，为16:9宽屏收银机优化的商业级应用。

**视觉基调**：深色专业风格，参考高端台球会所的沉稳氛围。使用深蓝灰色调搭配金色点缀，营造专业、商务、高端的服务体验。界面强调信息密度与操作效率的平衡，让收银员快速完成日常操作。

**核心体验**：台球桌可视化看板为核心，一眼掌握全场状态；操作流程扁平化，减少点击层级；关键操作一步直达，支持快捷键操作。

## 4. Features & Interactions

### 4.1 台球桌看板

#### 网格模式
- 每行5桌，大尺寸卡片(180x140px)
- 显示：桌号、状态、时间(使用中)、价格(使用中)
- 状态颜色边框，左上角状态标签
- 悬停：卡片微抬升 + 边框高亮
- 点击：打开台球桌详情抽屉

#### 列表模式
- 紧凑行显示，每行信息完整
- 列：桌号、状态、时长、当前消费、助教、操作
- 支持按状态筛选
- 支持搜索桌号

#### 状态筛选
- 全部 / 空闲 / 使用中 / 预约 / 清洁中

### 4.2 开台操作
**入口**：
- 点击空闲桌 → 详情抽屉 → "开台"按钮
- 快捷面板 → "开台" → 弹窗选择桌号

**流程**：
1. 选择人数 (1-10人，默认1)
2. 选择助教 (可选，从列表选择或跳过)
3. 选择时长套餐 (默认按时计费)
4. 确认开台 → 计时开始

**套餐类型**：
- 时计：¥XX/小时
- 畅打：¥XX/4小时
- 包场：¥XX (全天)

### 4.3 关台操作
**入口**：使用中的桌 → 详情抽屉 → "关台"按钮

**流程**：

### 6.3 API Endpoints

#### Tables
- `GET /api/tables` - 获取所有台球桌
- `POST /api/tables/:id/open` - 开台
- `POST /api/tables/:id/close` - 关台
- `POST /api/tables/:id/merge` - 并台
- `POST /api/tables/:id/transfer` - 换台

#### Orders
- `GET /api/orders?tableId=` - 获取订单列表
- `POST /api/orders` - 创建订单
- `PUT /api/orders/:id` - 更新订单
- `POST /api/orders/:id/items` - 添加订单项

#### Payments
- `POST /api/payments` - 创建支付记录
- `POST /api/payments/coupon` - 核销优惠券

#### Members
- `GET /api/members?phone=` - 查询会员
- `POST /api/members` - 创建会员
- `POST /api/members/:id/recharge` - 会员充值
- `POST /api/members/:id/points` - 积分抵扣

#### Shifts
- `GET /api/shifts` - 获取班次列表
- `POST /api/shifts/start` - 开始班次
- `POST /api/shifts/:id/end` - 结束班次

#### Sync
- `POST /api/sync` - 离线数据同步

### 6.4 Offline Strategy
1. **IndexedDB** 存储本地数据
2. **操作队列**：离线时的操作记录到队列
3. **网络检测**：navigator.onLine + 定时心跳
4. **自动同步**：网络恢复后按序执行队列
5. **冲突处理**：服务端时间戳优先

### 6.5 Performance
- 台球桌看板使用虚拟化（如桌数>50）
- 计时器使用单一定时器，所有使用中的桌共享
- 商品列表支持懒加载
- 图片使用 WebP 格式
